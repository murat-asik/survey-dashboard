1. Yönetici Özeti

Bölgesel Anket Veri Analiz Platformu, 26 bölge ofisine ait anket veri kalitesi metriklerini interaktif harita üzerinde görselleştiren modern bir web uygulamasıdır.

Proje Hedefi: 2021-2025 yılları arasındaki Yanıt Oranı, Analiz ve Tamamlılık verilerinin kullanıcı dostu bir arayüzle sunulması ve karar vericilere hızlı analiz imkanı sağlanması.

Temel Başarılar

  • 5 yıllık veri setinin tek platformda birleştirilmesi
  • İnteraktif harita ile görsel analiz imkanı
  • Responsive tasarım ile tüm cihazlarda erişilebilirlik
  • Yüksek performans ve kullanıcı deneyimi

2. Proje Tanımı ve Amaç

2.1. Proje Kapsamı

Sistem, 26 bölge ofisinden toplanan verileri analiz ederek üç temel metriği görselleştirir:

Metrik Açıklama Hesaplama
Cevaplılık Kurumların veri sağlama oranı (Cevaplanan / Toplam) × 100
Analiz Analiz edilen veri oranı (Analiz Edilen / Toplam) × 100
Tamamlılık Tam ve eksiksiz veri oranı (Tamamlanan / Toplam) × 100

2.2. İş Gereksinimleri

  • Yıl bazlı veri filtreleme (2021-2025)
  • Ay bazlı çoklu seçim imkanı
  • Bölge bazlı detaylı istatistikler
  • Renk kodlu görsel analiz
  • Excel formatında veri desteği

6. Veri Yapısı ve İşleme

6.1. Excel Veri Formatı

Sütun Adı Veri Tipi Açıklama Örnek Değer
ORG_CODE Number Benzersiz organizasyon kodu 12345
YIL_REF Number Veri yılı 2025
AY_REF Number Ay numarası (1-12) 11
REGION_ID Number Bölge kodu (4 haneli) 0600 (Ankara)
YANIT_DURUMU Number Yanıt durumu (0 veya 1) 1
ANALIZ_KAYNAK Number Analiz kaynağı (0 veya 1) 1
KAYIT_STATU Number Kayıt statüsü (0 veya 1) 0
Önemli Not: Bölge kodları 4 haneli olarak saklanır. Ankara: 0600, Adana: 0100, Antalya: 0700 gibi. Başındaki sıfırlar önemlidir ve korunmalıdır.

Harita, %0 ile %100 arasındaki değerleri renk gradyanı ile gösterir:

  • %0-25: Kırmızı tonları (Düşük performans)
  • %25-50: Turuncu-Sarı tonları (Orta performans)
  • %50-75: Sarı-Yeşil tonları (İyi performans)
  • %75-100: Yeşil tonları (Mükemmel performans)

Performans Testi Nasıl Yapılır?

1. Tarayıcı DevTools ile Test:
• Chrome/Edge'de F12 tuşuna basın
• "Network" sekmesine gidin
• Sayfayı yenileyin (Ctrl+R)
• "DOMContentLoaded" ve "Load" sürelerini kontrol edin
• Hedef: DOMContentLoaded < 1.5s, Load < 2s
2. Lighthouse ile Analiz:
• Chrome DevTools'da "Lighthouse" sekmesini açın
• "Performance" seçeneğini işaretleyin
• "Analyze page load" butonuna tıklayın
• Hedef: Performance Score > 90
3. React DevTools Profiler:
• React DevTools eklentisini yükleyin
• "Profiler" sekmesine gidin
• Kayıt başlatın ve yıl/veri türü değiştirin
• Render sürelerini inceleyin
• Hedef: Her render < 16ms (60 FPS için)

8.2. Optimizasyon Teknikleri

React Optimizasyonları

  • useMemo: Pahalı hesaplamaların cache'lenmesi

  • Conditional Rendering: Gereksiz render'ların önlenmesi

Veri Optimizasyonları

  • Filtreleme: Sadece gerekli verinin işlenmesi
  • Lazy Loading: İhtiyaç anında veri yükleme

CSS Optimizasyonları

  • CSS Variables: Dinamik tema yönetimi

9. Güvenlik

9.1. Güvenlik Önlemleri

Tehdit Önlem Uygulama
XSS Saldırıları React DOM Sanitization Otomatik escape işlemi
Type Errors TypeScript Compile-time kontrol
Invalid Data Input Validation Veri doğrulama fonksiyonları
Cache Poisoning Cache Control Headers No-cache policy

Güvenlik Önlemleri Detayları

1. XSS (Cross-Site Scripting) Koruması:

React, varsayılan olarak tüm kullanıcı girdilerini otomatik olarak escape eder. Örneğin:

// Güvenli - React otomatik escape yapar <div>{userInput}</div> // Tehlikeli - Sadece güvenilir içerik için <div dangerouslySetInnerHTML={{__html: content}} />

Projemizde dangerouslySetInnerHTML sadece tooltip içeriği için kullanılır ve içerik tamamen sistem tarafından üretilir, kullanıcı girdisi içermez.

2. TypeScript Tip Güvenliği:

Tüm veri yapıları TypeScript interface'leri ile tanımlanmıştır:

interface ExcelRow { KURUM_KEY: number; REFERANS_YIL: number; REFERANS_AY: number; REGION_ID: number; // ... diğer alanlar }

Bu sayede yanlış tip kullanımı compile zamanında yakalanır ve runtime hataları önlenir.

3. Input Validation:

Excel verisi yüklendikten sonra doğrulama yapılır:

// Bölge kodu kontrolü if (!excelRegionCode) return false; // Yıl kontrolü if (selectedYear) { filteredData = filteredData.filter(row => Number(row.REFERANS_YIL) === selectedYear ); } // Ay kontrolü (1-12 arası) if (selectedMonths && selectedMonths.length > 0) { filteredData = filteredData.filter(row => selectedMonths.includes(Number(row.REFERANS_AY)) ); }
4. Cache Poisoning Koruması:

Excel dosyası her yüklendiğinde timestamp ile cache bypass yapılır:

const timestamp = new Date().getTime(); const urlWithTimestamp = `${filePath}?t=${timestamp}`; fetch(urlWithTimestamp, { cache: 'no-store', headers: { 'Cache-Control': 'no-cache, no-store, must-revalidate', 'Pragma': 'no-cache', 'Expires': '0' } });

Bu sayede eski/bozuk cache verisi kullanılmaz, her zaman güncel veri yüklenir.

9.2. Veri Güvenliği
